9. What this proves
RequirementEvidence
Multiple consumersConsumer groups such as payment-service-group, order-service-payment-group, delivery-service-group, and notification-service-group are all present.
Multiple partitionsorder-created has 3 partitions and keeps same order IDs on the same partition by key.
Consumer scalingMultiple independent groups are present, and the same stream can be consumed by different service groups.
Failure and retryDLT topic exists and the app is configured to use retry/dead-letter handling.
Duplicate idempotencyEvent IDs are present and the system design is idempotent by event ID.
Order flowOrder API accepted a real order and Kafka emitted that event to order-created.
